# Issue #218 — JWKS per-kid negative cache and coalescing tests

Follow-ups from the #208 review (Grok 4.7 at `5235756f`).

## Problem

The 60s forced-refresh throttle was **per cache**: any unknown `kid` (including garbage) set `last_forced_refresh_at`, so a legitimately new `kid` published seconds later could not trigger another JWKS fetch for up to 60s.

Coalescing on `refresh_lock` was only covered when the in-flight fetch **succeeds**; a regression that moved `last_forced_refresh_at` to after a successful assignment would not be caught on failed or slow fetches.

## Change

In `activity_bridge.py`:

- **Per-`kid` negative cache** (`forced_refresh_negative_kids`: LRU `OrderedDict`, max **128** entries). After a forced refresh is attempted for `unknown_kid`, that `kid` is not refetched for **`JWKS_FORCED_REFRESH_MIN_INTERVAL_SECONDS` (60s)**.
- **Global floor**: **`JWKS_FORCED_REFRESH_GLOBAL_MIN_INTERVAL_SECONDS` (1s)** between any two forced JWKS fetches on one cache (~60/min worst case for distinct `kid` spam; single-`kid` spam remains 1 fetch / 60s).
- `last_forced_refresh_at` is still stamped **before** the await on `fetch()` so waiters on `refresh_lock` honour the pre-fetch throttle.
- `validate_inbound_jwt` / `validate_inbound_jwt_bf` pass `unknown_kid=kid` into `_refresh_jwks`.

## Tests

- Updated `test_unknown_kid_within_forced_interval_fails_without_extra_fetch` behaviour unchanged (same `kid`, still throttled 60s).
- `test_forced_refresh_throttled_within_min_interval`: per-`kid` throttle + different `kid-b` can fetch within the 60s window (after global 1s).
- `test_garbage_kid_does_not_block_different_unknown_kid`: real `validate_inbound_jwt` + `httpx.MockTransport`.
- `test_concurrent_forced_refresh_coalesces_when_fetch_raises` / `…_when_fetch_hangs`: coalescing and pre-fetch stamp on `_refresh_jwks`.

## Bounds summary

| Knob | Value |
|------|-------|
| Per-`kid` no-refetch window | 60s |
| Negative-cache LRU size | 128 `kid`s |
| Global min interval between forced fetches | 1s |

Tokens whose `kid` is absent from a freshly fetched JWKS are still rejected (fail closed).
