# #256 — register apply treats blueprint CLI output as sensitive

## Problem

`hermes-a365 register --apply` ran `a365 setup blueprint` through the default streaming mutator path, so credential material emitted once by the GA CLI could appear in terminal scrollback or CI logs. The az credential-recovery path already used captured sensitive runs.

## Change

- Blueprint apply steps call `Mutator.run(..., sensitive=True)` (including license-retry replays and Entra repair plans that re-run blueprint).
- Sensitive runs capture child stdout/stderr via bounded chunk reads and threaded pumps (POSIX and Windows).
- When a complete device-login prompt is recognised (strict full-line MSAL shape, allowlisted URL, validated user code), the mutator prints a fresh operator message containing only those fields; raw CLI lines are never replayed and partial lines are never evaluated mid-chunk.
- Timeouts raise without attaching captured output; sensitive CLI failures keep the suppression placeholder (AADSTS code and return code unchanged).

## Tests

Adversarial fake-child subprocess tests cover co-mingled output, ANSI/CR splits, long lines, banner+prompt chunks, hung partial lines, failure paths, and register apply (first run + repair).
